# Internationalization (i18n)

## Languages
The home page supports three languages, in this order of priority:

| Code | Name | Role |
|---|---|---|
| `zh-Hant` | Traditional Chinese | default and fallback |
| `zh-Hans` | Simplified Chinese | |
| `en` | English | |

## Where strings live
- **Static UI on the home page** → the `I18N` table in `js/main.js`, referenced from HTML with
  `data-i18n`, `data-i18n-aria`, `data-i18n-title`, `data-i18n-placeholder`. Keep the default
  zh-Hant text inline in `index.html` too, so the page reads correctly before JS runs.
- **Data** (`assets/data/*.json`) → a field is either a plain string (same in every language — use for
  proper nouns like "Spark") or an object with **all three** keys:
  `{ "zh-Hant": "…", "zh-Hans": "…", "en": "…" }`. The validator rejects partial objects.
- **Project pages** (`projects/<id>/`) choose their own language(s); they don't use the home page
  i18n system. Keep each page internally consistent (`english-toolbox` UI is zh-Hant; `chinese-toolbox`
  UI is English for learners of Chinese).

## Writing rules
- Write zh-Hans as a real Simplified version (vocabulary too: 視覺化 → 可视化, 專案 → 项目,
  資料 → 数据), not just a character conversion.
- English: natural, concise, sentence case for labels. Don't translate product names.
- Keep the three versions equivalent in meaning and similar in length (cards have limited space).
- Adding a key to one language means adding it to all three in the same commit.
